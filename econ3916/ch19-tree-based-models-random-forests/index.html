Gini Impurity: The Split Criterion

How "mixed" is this group?

$$G(p) = 1 - \sum_{k=1}^{K} p_k^2$$

  • \(G = 0\) → perfectly pure (all one class)
  • \(G = 0.5\) → maximally impure (50/50 mix)

Worked example: Node has 80 pos, 20 neg
\(G = 1 - (0.80^2 + 0.20^2) = 1 - 0.68 = 0.32\)

Work through the calculation on the board.

Have students shout out each step.

Why Squaring Punishes a Mixed Node

Squaring rewards concentration. A node that is nearly all one class has a large ∑p², so G = 1 − ∑p² falls toward zero — which is what pushes the tree toward clean separation.

Show the subtraction. That is the step they skip.

Sum of squares and Gini are not the same number. Squaring rewards concentration, so a pure node has a LARGE sum of squares and therefore a SMALL Gini. Students who memorise “squaring punishes minorities” get the direction backwards on the exam.

How the Tree Chooses Splits

$$\Delta G = G(\text{parent}) - \left[\frac{n_L}{n}\, G(\text{left}) + \frac{n_R}{n}\, G(\text{right})\right]$$

The algorithm evaluates every feature and every threshold , picking the split that maximizes impurity reduction.

Greedy: Locally optimal at each step. No global lookahead.

Regression: Replace Gini with MSE. Predict \(\bar{y}_{\text{leaf}}\).

The algorithm is greedy — it makes the locally optimal choice at each step without looking ahead.

The Variance Problem

Why Single Trees Fail

Section two. The problem, before the solution.

Resist jumping to random forests. They will not appreciate the fix until they have felt a single tree move under them.

Change a Few Rows, Get a Different Tree

Two samples of 8,000 California block groups, differing only in a handful of rows. The tree picks its root split by whichever threshold happens to cut Gini best in that batch — so the batch's noise decides the first question the model ever asks.

Two samples, one differs a little, the root question changes.

The root split is the first question the model ever asks, and a handful of rows decided it. Everything below the root is now a different tree. Note the units: median income is in tens of thousands, so 5.03 is about $50,300, and the gap is roughly $1,600.

Single Trees: Flexible but Unstable

Small data changes → entirely different trees.

Tree A: MedInc > 5.03 (root split)
Tree B: MedInc > 4.87 (root split)
By level 3: almost no splits in common

The solution: If B independent estimators each have variance σ², their average has variance σ²/B.

Same principle as the Central Limit Theorem.

What if we just built a hundred trees and averaged them?

Bagging

Bootstrap Aggregating (Breiman, 1996)

Section three. Bagging, then what bagging cannot fix.

Bagging is half the answer. Ending the section without the correlation floor leaves them thinking more trees is always the lever.

How Bagging Works

  1. Draw B bootstrap samples (with replacement)
  2. Train one decision tree on each sample
  3. Average predictions: \(\hat{f}_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^{B}\hat{f}_b(x)\)

OOB: Each tree misses ~37% of observations → free cross-validation

Bootstrap samples share about 63% of observations.

The trees are not independent — they are correlated.

Every Tree Only Sees Two Thirds of the Data

Draw 100 rows with replacement from 100 rows. Some get picked twice or more; some never get picked at all.

One real draw, not an illustration — 63 in, 37 out.

It is a real draw, so ask them to count.

63 shaded, 37 white, from one actual bootstrap of 100 rows. Ask why any cell is labelled twice before you explain replacement — they will get there.

The 37% You Left Out Is a Free Test Set

Each tree is grown on its own bootstrap sample, so each tree has its own leftovers — rows it never saw. Score the tree on those and you get honest validation without holding anything back up front.

Free validation, and they get it per tree.

No data was held back up front. Each tree has its own leftovers, and averaging those scores is the OOB estimate. Contrast with a train/test split, where you pay for validation by not training on it.

The Correlation Floor

$$\text{Var}(\bar{f}) = \underbrace{\rho\sigma^2}_{\text{FLOOR}} + \underbrace{\frac{1-\rho}{B}\sigma^2}_{\text{shrinks with B}}$$

First term \(\rho\sigma^2\): Stays no matter how many trees. This is the floor.

Second term: Shrinks toward 0 as B → ∞. This is the averaging benefit.

The question: can we reduce ρ?

This is the most important equation in the lecture.

Circle the first term. No matter how many trees, you cannot push variance below this floor.

Numerical Example: Bagging

\(\sigma^2 = 0.50\), \(B = 100\) trees, \(\rho = 0.85\) (bagging)

\(\text{Var} = 0.85 \times 0.50 + \frac{0.15}{100} \times 0.50 = 0.425 + 0.001 = \mathbf{0.426}\)

The floor is 0.425. Adding more trees barely helps — we are stuck.

To go lower, we need to attack ρ.

Random Forests

Breaking the Correlation Floor (Breiman, 2001)

Section four. The one idea that separates a forest from bagging.

Feature randomisation. If they leave remembering one mechanism, this is the one.

Hiding Features on Purpose

At every split, the tree may only look at a random subset of the features. Starve it of the dominant predictor often enough and the trees stop agreeing — which is the ρ you are trying to lower.

Check this in the lab. √p is RandomForestClassifier's default. RandomForestRegressor does not default to p/3 — scikit-learn uses max_features=1.0, every feature, so the trees stay correlated unless you set it yourself.

Starving the tree is the point, not a compromise.

It feels wrong to hide the best predictor. That is exactly what lowers ρ. Flag the lab trap while it is on screen: √p is the classifier default, but the REGRESSOR defaults to every feature, so they must set max_features themselves or they get no decorrelation at all.

Gold = true function • Blue = ensemble • Slide B: 1 → 100 trees

Run it twice with different seeds so they see the spread shrink.

One tree jumps around; the average barely moves. That is variance reduction happening in front of them rather than in an equation.

Accuracy and Stability at the Same Time

The trade-off says you pick one: flexible and unstable, or stable and too simple. Averaging decorrelated trees is how you stop having to pick.

R² on held-out listings. The tree and the forest are equally flexible — the forest just is not betting on one tree’s idiosyncrasies.

Two numbers are nearly equal, and that is the interesting part.

The tree and ridge land within 0.01 of each other for opposite reasons — one too flexible, one too rigid. Ask which they would rather ship before revealing the forest.

Common Misconception

"More trees = overfitting"

Reality: Adding trees does NOT increase overfitting. The \((1-\rho)/B\) term decreases monotonically.

RF CAN overfit through:

  • max_depth too high (trees memorize)
  • max_features too close to p (trees correlate)

n_estimators is the one hyperparameter you can safely increase.

Read the reality line aloud, then the two real routes to overfitting.

Adding trees is safe. max_depth and max_features are not. n_estimators is the one hyperparameter they can raise without thinking, and it is worth saying that plainly.

Two Ways to Ask “Which Feature Mattered?”

Mean decrease in impurity

How: add up how much each feature reduced Gini across every split. Free — it falls out of training.

Flaw: biased toward features with many possible split points. A continuous variable like exact income can look important merely because it offers more places to cut.

Permutation importance

How: shuffle one column, re-score the fitted model, and see how much accuracy falls. Costs a pass per feature.

Why it is better: it measures what the model actually loses without that feature, so split granularity cannot flatter anything.

Neither one is causal. Both answer “what is this model leaning on?” — never “what would change the outcome if we intervened?”

The difference is where the number comes from.

MDI is computed during training and is biased toward whatever offers more places to split. Permutation asks what the fitted model actually loses. Land the last line hard: neither is causal, which is what the decision scenario is about to test.

Decision Scenario: The Feature Importance Trap

You advise a bank on mortgage default prediction. Random Forest achieves excellent AUC. Feature importance: "prior credit inquiries" is #1.

The CRO says: "Reject anyone with > 3 inquiries."

What is wrong with this reasoning?

Feature importance measures prediction, not causation.

People about to default take out MORE inquiries because they're desperate for credit.
