No block here is unique. The sequence is.

Topics 1–10 · Foundations
Ground they met in ECON 5140 — but this is the first time doing it in Python, on data that arrives dirty. Revisions, vintages, missing periods.

Topics 14–23 · Prediction
Overlaps ECON 5210, and we say so. It is here because regularization and cross-fitting are the machinery double machine learning runs on.

Topics 11–13, 24 · Identification
DiD, IV, RD — which ECON 6140 also covers — then double machine learning, where the two halves finally join.

Each block exists elsewhere. Remove any one of them and the capstone stops working — you cannot run double machine learning without the prediction block, and you cannot interpret it without the identification block.

What comes out is a replicated published paper and a deployed causal tool with quantified uncertainty. 5140, 5210 and 6140 do not produce that, individually or in sequence — because nobody takes them in one.

The course is defined by its outcomes

Any instructor teaching it would teach to these. They are the catalog specification, not a description of how I happen to run it.

1Formulate an identification strategy, state its maintained assumptions, and propose tests that could falsify it
2Estimate causal effects — randomized, DiD, IV, RD, double machine learning — with appropriate diagnostics
3Build and evaluate predictive models against economically meaningful loss functions
4Assess whether a predictive result supports a causal interpretation
5Integrate generative AI into an analytics workflow in a documented and verifiable way
6Replicate and critique published research, and deliver a quantified recommendation reporting its uncertainty

THIS PRE-EMPTS THE STAFFING OBJECTION, which is the most common reason a permanent-status request stalls. The worry is never “is it good”, it is “what happens when he stops teaching it.” A specification answers that; a personal syllabus does not.

If AI can write the code, what is being assessed?

The defence, not the artifact. A fifth of the final project’s marks — about 5% of the course — is a recorded walkthrough plus adversarial review, where each student must answer substantive questions posted on their repository by two assigned classmates.

AI use is declared, not banned. Every project carries a methodology appendix documenting where AI was used and how its output was verified.

The labs invert the task. Students diagnose code they did not write — generation is the cheap part, judgment is what is graded.

Two quizzes under LockDown Browser with camera and screen recording set an individual floor.
